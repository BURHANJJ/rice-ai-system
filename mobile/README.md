# Rice AI — Mobile (Flutter)

Farmer-facing mobile app: scan a rice leaf photo, get an AI diagnosis with
treatment advice, browse the disease encyclopedia, see outbreak status by
province, and view your own diagnosis history.

## Status of this folder

This is a **hand-written Flutter source tree**, not a project generated by
`flutter create` — the sandbox used to build this handoff does not have the
Flutter SDK installed, so **this code has not been compiled or run**. The
structure, imports, and API usage follow current (2024/2025-era) Flutter +
package conventions and mirror the same backend contract already verified
working against the Node.js backend (see `/backend`) and the working web
app (see `/web`), but you should treat first-build errors (missing
`android/`, `ios/` platform folders, small API drift in a pinned package
version, etc.) as expected and quick to fix, not a sign of deeper design
problems.

## To get this running

```bash
# 1) Scaffold platform folders (this generates android/, ios/, etc. — not included here)
flutter create --project-name rice_ai_mobile --org com.example .

# 2) Install dependencies
flutter pub get

# 3) Point the app at your backend (see lib/services/api_service.dart)
flutter run --dart-define=API_BASE=http://10.0.2.2:4000   # Android emulator
flutter run --dart-define=API_BASE=http://localhost:4000  # iOS simulator
```

You'll also need to add platform permissions after `flutter create` runs:
- **Android** (`android/app/src/main/AndroidManifest.xml`): `CAMERA`,
  `ACCESS_FINE_LOCATION`, `INTERNET`.
- **iOS** (`ios/Runner/Info.plist`): `NSCameraUsageDescription`,
  `NSPhotoLibraryUsageDescription`, `NSLocationWhenInUseUsageDescription`.

## Structure

```
lib/
  main.dart                  — app entrypoint, root router (login vs home)
  theme/app_theme.dart       — design tokens shared with /web
  services/
    api_service.dart         — HTTP client for the backend REST API
    auth_provider.dart       — auth state (login/2FA/register/logout)
  models/diagnosis.dart      — DiagnosisResult, HistoryEntry, ProvinceStat
  screens/
    auth/                    — login (incl. researcher 2FA step), register, apply-researcher
    home_shell.dart          — bottom-nav shell (5 tabs)
    scan/                    — camera/gallery capture, GPS, AI result
    history/                 — this user's diagnosis history
    wiki/                    — disease encyclopedia (read-only on mobile)
    outbreak/                — 77-province outbreak list (farmer view)
    profile/                 — profile + logout
```

## Scope notes

- This app implements the **farmer** role end-to-end. Researcher and Admin
  workflows (data explorer/export, dashboards, user management, wiki CRUD,
  the full choropleth risk map) live in **`/web`** — per the handoff's own
  role matrix (section 5), those are desk-work flows better suited to a
  larger screen, and building a second full implementation of them in
  Flutter was out of scope for this pass. The login screen here does
  accept researcher/admin credentials (including the 2FA step) for
  completeness, but currently routes them to the same farmer-oriented tabs.
- TFLite on-device inference (an option floated in the handoff) is **not**
  implemented; this app always calls the backend `/diagnosis/predict`
  endpoint (server-side inference), consistent with the locked
  architecture decision documented in `ai-service/main.py` and
  `docs/ASSUMPTIONS_AND_TODOS.md`.
